# Installing Voice Agent on a fresh device

A complete, from-scratch guide — assumes you're starting with a brand new Mac (or
PC) and a brand new Android phone, with nothing set up yet. Every step includes the
exact command to run.

This app cannot be installed like a normal app from the Play Store — it's a
development project you build and load onto the phone yourself using a cable. That's
normal for an app built like this one (with a fully custom on-device AI engine); it's
not a shortcut you're missing.

---

## Part 1 — Set up your computer (one-time)

You need three things on your computer before you can build anything: Node.js, Java,
and the Android SDK/NDK.

### 1.1 Install Node.js

Node.js runs the build tooling (Angular, Cordova). Download and install it from
[nodejs.org](https://nodejs.org) — pick the LTS (Long Term Support) version. This
also installs `npm`, which you'll use to run build commands.

Verify it worked:
```bash
node -v
npm -v
```
Both should print a version number, not "command not found".

### 1.2 Install Java (JDK)

Android's build tools need Java. Install a recent JDK (version 17 or newer) — on a
Mac, the easiest way is:
```bash
brew install openjdk@21
```
(If you don't have Homebrew, install it first from [brew.sh](https://brew.sh).)

Verify:
```bash
java -version
```

### 1.3 Install the Android SDK, NDK, and build tools

The **NDK** (Native Development Kit) is essential here — this app compiles a real C++
AI engine (llama.cpp), not just Java/Kotlin code, so a plain "Android SDK" isn't
enough.

Install the Android command-line tools (via Homebrew on a Mac):
```bash
brew install --cask android-commandlinetools
```

Then install the specific SDK pieces this project needs:
```bash
export ANDROID_HOME=/opt/homebrew/share/android-commandlinetools
export PATH="$ANDROID_HOME/cmdline-tools/latest/bin:$ANDROID_HOME/platform-tools:$PATH"
yes | sdkmanager --licenses
sdkmanager --install "platform-tools" "platforms;android-36" "build-tools;36.0.0" "cmake;3.22.1" "ndk;26.1.10909125"
```
This is the single largest download in this whole setup (several GB — mostly the
NDK) and can take a while depending on your internet connection.

**Tip:** add the two `export` lines above to your shell profile (`~/.zshrc` or
`~/.bash_profile`) so you don't have to retype them every time you open a new
terminal.

### 1.4 Install Cordova

```bash
npm install -g cordova
```
(If this fails with a permissions error, see the note about local wrapper scripts in
this project's `.devtools/` folder — that's a workaround this project used when the
global `npm` install itself was broken on the dev machine, not required if your Node
install is healthy.)

## Part 2 — Set up the phone (one-time per phone)

### 2.1 Enable Developer Options

1. Open **Settings** → **About phone**
2. Find **Build number** and tap it **7 times** in a row. You'll see a countdown
   toast ("You are now 3 steps from being a developer" etc.)
3. Go back to the main Settings screen — you'll now see a new **Developer options**
   entry (usually under **System**)

### 2.2 Enable USB Debugging

1. Open **Settings** → **System** → **Developer options**
2. Turn on **USB debugging**

### 2.3 Connect the phone and authorize this computer

1. Plug the phone into your computer with a **data-capable USB cable** (some cheap
   cables only carry power, not data — if the next step never shows anything, try a
   different cable first)
2. On the phone, a popup should appear asking "Allow USB debugging from this
   computer?" — tap **Allow**, and check **"Always allow from this computer"** so you
   don't have to approve it every time
3. Verify the computer sees the phone:
   ```bash
   adb devices -l
   ```
   You should see your phone listed with a status of `device` (not `unauthorized` —
   if you see that, look at the phone screen for the popup and tap Allow).

If nothing shows up at all, double check: a data cable (not charge-only), a direct
USB port (not through a hub if avoidable), and that USB debugging is actually toggled
on.

## Part 3 — Get the project and its dependencies

### 3.1 Get the project files

If you're copying this project from another machine, copy the whole
`voice-agent-app` folder over (excluding `node_modules/`, `cordova-app/platforms/`,
and `cordova-app/plugins/` — those get regenerated by the build and don't need to be
copied).

### 3.2 Install the JavaScript dependencies

```bash
cd voice-agent-app
npm install
cd angular-app && npm install && cd ..
```

### 3.3 Add the Android platform to the Cordova project

```bash
cd cordova-app
cordova platform add android
```

### 3.4 Add the plugins

```bash
cordova plugin add cordova-plugin-speechrecognition
cordova plugin add cordova-plugin-tts
cordova plugin add cordova-plugin-statusbar
cordova plugin add cordova-plugin-camera
cordova plugin add ../plugins-src/local-llm-plugin
cd ..
```

The last one (`local-llm-plugin`) is the custom one built for this project — it
compiles the on-device AI engine. This step can take a minute or two the first time
since it's compiling real C++ code.

---

## Part 4 — Build and install the app

### 4.1 Build

From the project root:
```bash
export ANDROID_HOME=/opt/homebrew/share/android-commandlinetools
export ANDROID_SDK_ROOT=$ANDROID_HOME
export ANDROID_NDK_HOME=$ANDROID_HOME/ndk/26.1.10909125
export PATH="$ANDROID_HOME/cmdline-tools/latest/bin:$ANDROID_HOME/platform-tools:$PATH"

npm run build
cd cordova-app
cordova build android
```
If this is the very first build, expect it to take several minutes (compiling the AI
engine from source). Later builds are much faster (tens of seconds) unless you change
the native code itself.

A successful build ends with a line like:
```
Built the following apk(s):
	.../cordova-app/platforms/android/app/build/outputs/apk/debug/app-debug.apk
```

### 4.2 Install the app onto the phone

```bash
adb install -r platforms/android/app/build/outputs/apk/debug/app-debug.apk
```
You should see `Success`. The app icon (a green glowing orb) will now appear on the
phone's home screen / app drawer as "Voice Agent".

**Don't open it yet** — it needs its AI model files first, or it won't be able to
answer anything.

## Part 5 — Install the AI models onto the phone

The AI models are too large to bundle inside the app itself, so they're copied onto
the phone separately, once. See [MODEL.md](MODEL.md) for the full explanation and the
exact current model choices — the short version:

```bash
# Text model (Qwen3-0.6B) — used for voice commands and general chat
curl -L -o models/qwen3-0.6b-instruct-q4_k_m.gguf \
  "https://huggingface.co/unsloth/Qwen3-0.6B-GGUF/resolve/main/Qwen3-0.6B-Q4_K_M.gguf"

# Vision model (SmolVLM2-2.2B) — used for the "Take photo" / "Choose photo" feature
curl -L -o models/smolvlm2-2.2b-instruct-q4_k_m.gguf \
  "https://huggingface.co/ggml-org/SmolVLM2-2.2B-Instruct-GGUF/resolve/main/SmolVLM2-2.2B-Instruct-Q4_K_M.gguf"
curl -L -o models/smolvlm2-2.2b-instruct-mmproj-q8_0.gguf \
  "https://huggingface.co/ggml-org/SmolVLM2-2.2B-Instruct-GGUF/resolve/main/mmproj-SmolVLM2-2.2B-Instruct-Q8_0.gguf"
```

Then push each one onto the phone (this pattern applies to all three files — repeat
for each, replacing the filename):
```bash
adb push models/qwen3-0.6b-instruct-q4_k_m.gguf /data/local/tmp/model.gguf
adb shell "cat /data/local/tmp/model.gguf | run-as com.nothing.voiceagent sh -c 'cat > files/qwen3-0.6b-instruct-q4_k_m.gguf'"
adb shell rm -f /data/local/tmp/model.gguf
```

**This step only works because the app is a debug build** (`run-as` requires it).
Uninstalling the app deletes these files — if you ever run `adb uninstall`, you'll
need to push the models again afterward. A plain `adb install -r` (upgrade in place)
does **not** delete them.

---

## Part 6 — Launch and test

```bash
adb shell am start -n com.nothing.voiceagent/.MainActivity
```
Or just tap the green orb icon on the phone itself.

You should see a dark screen with a glowing orb and "Tap to speak" beneath it. Try:
- Tapping the orb and asking a question out loud
- Tapping **Take photo** or **Choose photo** and letting it describe an image

The very first voice command or photo will be slower than normal (the AI model has
to load into memory the first time) — after that, responses should come back in a
few seconds.

## Troubleshooting quick reference

| Problem | Likely cause |
|---|---|
| `adb devices` shows nothing | Bad cable (charge-only), USB debugging not enabled, or need to tap "Allow" on the phone |
| Build fails mentioning `cmake.path` | The plugin wasn't freshly re-added after an edit — see MODEL.md's "One-time build setup" |
| Local LLM takes minutes instead of seconds | Something reverted the Release build optimization — see MODEL.md's build gotchas |
| App crashes or says model not found on launch | Model file wasn't pushed, or the filename doesn't exactly match what the app expects |
| Everything worked before, now the AI doesn't respond | You probably ran `adb uninstall` — the model files get wiped and need re-pushing |
